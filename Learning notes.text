Mature projects have this structure per app
app/
  serializers.py    # request/response classes (one per shape)
  views.py          # slim controllers, call services, hand to serializers
  services.py       # business logic
  repositories.py   # DB access
  models.py



Serializers are like combined Laravel Resource and Request classes. 
Serializer.is_valid() = form validation
Serializer.data = response resource structure
There are other options available if they are too verbose e.g. (Pydantic / django-ninja)




Routing Files:
path() in xxx/urls.py registers routes
Entry point for registering all routes is urlpatterns in config/urls.py
URLResolver("")                       ← built from config.urls.urlpatterns
└── URLResolver("api/")               ← path("api/", include(api_urlpatterns))
    ├── URLResolver("")               ← include("core.urls")
    │   └── URLPattern("health")      ← path("health", HealthView.as_view(), name="health")
    ├── URLPattern("schema")          ← api_urlpatterns
    ├── URLPattern("docs")            ← api_urlpatterns
    └── URLPattern("redoc")           ← api_urlpatterns
